분산 훈련 프레임워크

정의

분산 훈련 프레임워크는 여러 프로세스·가속기·노드에서 모델 상태, 데이터 분할, 통신 집합과 체크포인트를 일관되게 관리하는 실행 계층이다. 2026-08-12 기준으로 PyTorch는 DDP, FSDP2, Tensor Parallel, Pipeline Parallel API를 서로 다른 확장 문제에 제시하며, DeepSpeed ZeRO와 Megatron-LM은 각각 상태 샤딩과 다차원 병렬화에 초점을 둔다.

원리와 알고리즘

  • DDP: 각 rank가 완전한 모델 복제본과 서로 다른 미니배치를 처리한다. autograd hook이 준비된 그래디언트를 버킷에 넣고 all-reduce하여 복제본을 동기화한다.
  • FSDP2: 파라미터를 DTensor로 rank 간 샤딩하고, 연산 전 all-gather와 역전파 후 reduce-scatter를 수행한다. 모델이 한 GPU에 들어가지 않거나 복제 상태 비용이 큰 경우가 주 대상이다.
  • DeepSpeed ZeRO: Stage 1은 옵티마이저 상태, Stage 2는 그래디언트까지, Stage 3은 파라미터까지 데이터 병렬 rank에 분할한다. CPU/NVMe offload는 GPU 메모리를 줄이지만 전송 경로를 추가한다.
  • Megatron-LM/Core: 텐서·파이프라인·데이터·시퀀스·컨텍스트·전문가 병렬 차원을 조합한다. 병렬 그룹별 collective와 P2P가 달라지므로 배치와 토폴로지를 함께 설계해야 한다.

선택 기준

조건우선 후보확인할 비용
모델이 GPU 한 장에 들어가고 복제 가능DDP그래디언트 all-reduce, 글로벌 배치 증가
모델 상태 복제가 메모리 한계FSDP2 또는 ZeROall-gather/reduce-scatter, 체크포인트 형식
큰 Transformer의 행렬·레이어 분할 필요Megatron-LM/CoreTP/PP 통신, 파티션 균형, 프레임워크 결합
CPU/NVMe 메모리까지 활용해야 함ZeRO offloadPCIe·스토리지 대역폭과 지연

백엔드는 하드웨어와 빌드에 맞춘다. CUDA GPU에서는 보통 NCCL process group을 검토하고, ROCm 배포에서는 PyTorch가 노출하는 nccl 백엔드가 RCCL을 통해 동작하는지 해당 빌드·컨테이너에서 확인한다. 라이브러리 이름만 보고 백엔드 가용성을 단정하지 않는다.

성능 측정

  1. 같은 모델·시퀀스·글로벌 배치·정밀도에서 단일 GPU 기준 처리량을 먼저 잰다.
  2. samples/s 또는 tokens/s, step time의 p50/p95, GPU 메모리 peak, 유효 연산률(MFU)을 기록한다.
  3. PyTorch Profiler와 Nsight Systems/rocprof로 compute, collective, 입력 대기 시간을 분리한다.
  4. 강한 확장 효율은 T_1 / (N × T_N)로 계산하되, OOM 때문에 단일 GPU 기준이 없으면 가장 작은 실행 가능한 구성과 비교했음을 명시한다.
  5. 체크포인트 저장·복구 시간과 장애 후 재시작 성공도 성능 계약에 포함한다.

실패 모드와 운영 고려사항

  • rank별 샘플 수나 collective 호출 순서가 다르면 hang 또는 잘못된 동기화가 발생한다.
  • DDP의 미사용 파라미터 탐색, FSDP wrap 경계, ZeRO stage를 바꾸면 통신 그래프와 메모리가 달라진다. 한 번에 하나씩 변경한다.
  • 통신 오버랩은 버킷이 너무 크거나 역전파 순서가 불안정하면 기대만큼 작동하지 않는다.
  • 샤딩 체크포인트는 world size·프레임워크 버전·state-dict API와 복구 절차를 함께 검증한다.
  • CUDA_VISIBLE_DEVICES, launcher 변수, NIC 선택 변수의 실제 값은 job 로그에 남기고 환경별 기본값을 문서에서 추정하지 않는다.
