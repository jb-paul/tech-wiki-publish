RTX 6000 계열 클러스터 레퍼런스 아키텍처

요약과 범위

신규 데이터센터 클러스터의 공식 설계 기준은 RTX PRO 6000 Blackwell Server Edition을 사용하는 NVIDIA RTX PRO AI Factory Enterprise RA다. RTX 6000 Ada 워크스테이션 카드를 같은 제품으로 취급하면 안 된다. 이 RA는 추론·파인튜닝·영상 생성·시각 컴퓨팅 등의 혼합 워크로드를 대상으로 8-GPU 노드와 Spectrum-X Ethernet 구성을 설명한다.[1][8]

  • 기준일: 2026-09-30. NVIDIA 문서의 latest는 고정 버전이 아니므로 접근일과 raw snapshot을 함께 보존했다.
  • 아래의 공식 구성은 제조사 문서 사실, 계산은 명시한 식의 산술 결과, 권고는 작성자의 설계 판단이다. 물리 클러스터 실측이나 인증 획득 결과가 아니다.
  • 원문에 대역폭 단위·NIC 개수·추론 용량 관련 불일치가 남아 있어 contested: true로 표시한다. 서로 다른 수치를 임의로 하나의 확정 BOM으로 합치지 않는다.

1. 제품명과 적용 범위부터 구분

  • NVIDIA RTX 6000 Ada Generation: 48GB GDDR6 ECC, PCIe Gen4 x16, 최대 300W, active cooling의 워크스테이션 GPU다. 공식 제품 페이지는 AI·렌더링·가상 워크스테이션 활용을 설명하지만, 이것이 아래 Blackwell Enterprise RA의 인증 대상이라는 뜻은 아니다.[8]
  • NVIDIA RTX PRO 6000 Blackwell Server Edition: 96GB GDDR7 ECC, PCIe Gen5, 제품 페이지상 메모리 대역폭 1597GB/s, 최대 600W configurable. 제품 페이지는 최대 4개 MIG instance와 공랭 dual-slot / 수랭 single-slot 폼팩터를 설명한다. RA는 공랭 가능한 RTX PRO Server를 중심으로 한다.[9][1]
  • Workstation Edition·Max-Q·구형 RTX A6000: 주문서에서 Server Edition 및 Ada와 반드시 분리한다. 이름의 6000만으로 서버 호환성·전력·메모리·partition 기능을 추정하지 않는다. 이 문서의 공식 클러스터 BOM은 Blackwell Server Edition 한정이다.[1]

설계 해석: 여기서 GPU 메모리는 HBM이 아니라 GDDR다. 노드 합계 768GB와 aggregate 12.8TB/s는 각각 8개 GPU의 용량·로컬 대역폭을 더한 RA 수치이며, 단일 GPU가 그 전체를 로컬 메모리처럼 사용하는 공유 풀이나 GPU 간 링크 대역폭이 아니다.[1]

원문 원문

2. 공식 기준 노드: 8 GPU + 4 SuperNIC + 1 DPU

RA는 이 구성을 **2-8-5-200**이라고 부르지만, 상세 네트워크 장과 부록의 실제 기준 BOM은 E/W에 400GbE를 사용한다. 따라서 이름의 200을 모든 포트의 속도로 해석하지 않는다.[1][4][7]

  • GPU: 8 × RTX PRO 6000 Blackwell Server Edition, CPU socket/root port에 균형 배치.[1]
  • CPU: 기준 예시는 2 socket. 부록은 socket당 최소 48 physical cores를 권고한다. 본문은 GPU당 최소 7 physical cores에 OS/가상화 추가 core, MIG instance당 최소 core 등 workload별 산정 조건을 따로 제시한다.[1][7]
  • Host RAM: GPU당 최소 128GB, 부록 권고는 1TB 이상. 계산상 8 × 128 = 1024GB; socket별 균등 배치와 memory channel당 DIMM 장착 조건을 함께 확인한다.[1][7]
  • PCIe: GPU당 최소 Gen5 x16. GPU·NIC·NVMe를 가능한 동일 PCIe switch/root complex에 두며, 불필요한 fanout이 없으면 direct attach를 우선한다. RA의 Gen6 switch 확장 언급을 기본 BOM으로 혼합하지 않는다.[1]
  • E/W: 4 × BlueField-3 B3140H SuperNIC, 각각 single-port 400GbE. GPU:NIC 비율은 기준 노드에서 2:1이다.[2][7]
  • N/S: 1 × BlueField-3 B3220 DPU, 2 × 200GbE를 서로 다른 switch에 연결한다.[2][4]
  • Local NVMe: 추론은 CPU socket당 최소 1TB, DL은 socket당 최소 2TB; 부록은 1TB boot drive를 별도로 제시한다.[7]
  • OOB: 서버 BMC와 DPU/SuperNIC 관리 포트용 1GbE 관리망을 구성한다.[4][7]

아래는 원문을 요약한 논리 연결도이며 특정 OEM의 PCIe slot 배선도나 승인된 포트맵은 아니다.[1][4]

권고: HGX/DGX의 NVSwitch 기반 scale-up 구조를 이 PCIe 기준 설계에 그대로 대입하지 않는다. GPU P2P·GPUDirect RDMA 가능 경로, PCIe switch uplink 공유율, socket 간 우회 경로를 OEM 블록도와 실측으로 확정한다. NIC 합계 대역폭이 충분해도 GPU→NIC 경로가 병목이면 실효 성능은 나오지 않는다.

3. 네트워크와 확장 단위

SU와 16·32노드 설계점

  • 1 SU = 4 compute nodes. SU당 E/W는 16 × 400Gb/s = 6.4Tb/s, N/S는 8 × 200Gb/s = 1.6Tb/s의 endpoint 합계다. 원문은 optimal conditions라는 조건을 붙이며 애플리케이션 실측값은 아니다.[4]
  • 16노드 / 128GPU / 4SU: E/W와 N/S를 통합한 collapsed fabric, VLAN으로 논리 분리하는 예시다. OOB까지 같은 보안 경계로 합치라는 뜻은 아니다.[4]
  • 32노드 / 256GPU / 8SU: E/W compute fabric을 별도 분리하는 예시다. RA는 4SU를 넘는 구성에 dedicated E/W fabric을 설명한다.[4]
  • Switch: SN5610의 hardware 장 표기는 64 × 800Gb/s, logical 장은 128 × 400GbE로 설명한다. 물리 포트와 breakout 후 논리 endpoint를 구별하고, 트랜시버·케이블·ISL·예비 포트를 포함한 포트맵으로 확인한다. OOB는 SN2201을 사용한다.[2][4]

권고: 문서의 rail-optimized/non-blocking 표현만 복사하지 말고 GPU rank→NIC→leaf 경로, cross-rail 통신, ISL 용량과 링크 장애 시 subscription을 확인한다. DGX B300의 64노드 SU나 GPU당 두 400GbE 경로는 별도 설계이므로 이 RTX PRO RA와 혼용하지 않는다. 비교 배경은 nvidia-amd-roce-reference-architectures를 참고한다.

대역폭을 올바르게 읽는 계산

기준 BOM인 4 × 400GbE / 8GPU를 계산하면 노드당 1.6Tb/s = 200GB/s, GPU 수로 균등 나눈 명목 몫은 GPU당 200Gb/s다. 이는 선속도 합계 기반 계산이며 RDMA payload 처리량 보장이 아니다. GPU당 400Gb/s 권고라는 별도 문구와 같은 값이 아니다.[1][4][7]

N/S의 2 × 200GbE는 이중 연결 구조다. 두 링크 합계가 항상 단일 flow의 유효 대역폭이 되는 것은 아니므로 storage protocol·multipath·DPU 처리 경로별로 확인한다. 원문은 최대 40GB/s/node라는 조건부 수치도 제시한다.[3]

4. 워크로드별 선택

A. 단일 GPU에 들어가는 모델의 독립 replica 추론

RA는 pure inference에서 E/W 전용망을 생략할 수 있다고 설명하지만, 이를 모든 추론 워크로드에 적용하면 안 된다. 모델·KV cache·workspace가 GPU 한 장에 들어가고, GPU 간 통신이 없는 독립 replica 배치인 경우에만 비용 절감 후보로 검토한다. 추후 fine-tuning이나 분산 serving을 추가하면 NIC·slot·케이블·다운타임 비용이 발생할 수 있다.[3]

권고: 우선 단일 GPU replica의 SLO 내 처리량을 기준선으로 측정한다. MoE, tensor/pipeline parallel serving, prefill/decode 분리, 긴 context처럼 통신·메모리 요구가 달라지는 경우에는 E/W를 다시 설계한다. 이 선택은 TP가 항상 느리다는 일반 법칙이 아니다.

B. 파인튜닝·영상 생성·혼합 enterprise AI

공식 기준인 8GPU 노드, E/W SuperNIC 4개, N/S DPU, 별도 OOB를 시작점으로 삼는다. RA가 목표로 하는 범위에는 중소형 언어 모델 추론·파인튜닝, 생성형 영상, recommender/vision, FP32 이하 HPC, rendering 등이 포함된다.[1]

권고: full pretraining의 대규모 TP/EP 통신이나 높은 FP64 처리량이 핵심이면 RTX PRO를 자동 선정하지 않는다. gpu-selection 기준으로 다른 accelerator platform과 동일 모델·동일 정확도·동일 병렬화 조건에서 비교한다. 작은 fine-tuning이라도 optimizer/activation 메모리를 추론 모델 가중치 용량만으로 산정하지 않는다.

C. 기존 RTX 6000 Ada 장비를 재사용하는 경우

작성자 제안이며 NVIDIA 인증 RA가 아님: OEM이 지원하는 Ada 노드를 독립 inference/render worker pool로 묶고, scheduler·공유 model storage·관측 체계를 공통화하는 구성부터 검토한다. 48GB 한계, PCIe Gen4, 300W active cooling이라는 Ada 사양을 유지한 별도 BOM을 작성한다.[8]

  • GPU 장수·호스트 RAM·NIC 속도를 Blackwell의 2-8-5-200에서 복사하지 않는다. 실제 chassis airflow, slot 간격, PSU와 OEM 지원 목록으로 node density를 정한다.
  • 모델이 한 GPU에 들어가면 replica scale-out을 먼저 검증한다. 분산 fine-tuning/TP가 필요하면 GPU pair별 P2P, NCCL transport와 inter-node scaling 시험을 통과한 조합만 채택한다.
  • Ada에 Blackwell의 MIG·96GB·Gen5 또는 Server Edition 인증을 적용하지 않는다. 이번 조사에서 확인한 공식 Enterprise RA는 Blackwell Server Edition용이며, Ada용 동등한 다중 노드 인증 설계를 확보했다고 주장하지 않는다.

5. 스토리지·운영·전력

  • 스토리지 공식 guideline: GPU당 약 12.5Gb/s를 할당한다. 8GPU 노드의 계산상 몫은 100Gb/s = 12.5GB/s다. 이는 설계 guideline이지 random IOPS·checkpoint 쓰기·동시 model load까지 보증하는 SLA가 아니다.[6]
  • Control plane: RA는 최대 8개 management/control-plane node 공간을 설명한다. 예시는 BCM HA 2대 + Slurm head 2대 + Kubernetes control plane 3대이며, 모든 배포에 세 stack을 동시에 설치해야 한다는 의미는 아니다.[1]
  • 소프트웨어: RA는 NVIDIA AI Enterprise/NIM/NeMo, Base Command Manager, Run:ai, vGPU, NetQ, Omniverse를 열거한다. 목록만으로 모든 SKU에 라이선스가 포함되거나 모든 조합이 검증되었다고 해석하지 않는다.[5]
  • Partition 운영: Server Edition 제품 페이지는 최대 4개 MIG instance를 설명한다. 실제 profile·driver·virtualization support·scheduler 노출과 재구성 절차는 구매 SKU 및 배포 버전에서 따로 확인한다.[9]
  • 전력 계산: GPU 8장을 각각 최대 600W로 잡으면 GPU만 4.8kW/node, 16노드 76.8kW, 32노드 153.6kW다. CPU·DIMM·NIC/DPU·NVMe·fan·PSU 손실과 switch/storage는 제외한 값이며 실제 소비전력 측정값이 아니다.[9]

권고: 전력 cap별 처리량·지연·성능/W를 비교하고, A/B feed 한쪽 상실 시의 허용 부하·PSU redundancy·흡기 온도·rack airflow를 함께 설계한다. 공랭 가능이라는 설명은 기존 저밀도 rack에 그대로 수용할 수 있다는 보장이 아니다. 공랭 RA와 수랭 GPU 옵션도 동일 시설 BOM으로 섞지 않는다. power-cooling, storage-solutions, cluster-monitoring와 연결해 운영한다.

원문 원문

6. 공식 원문의 불일치와 발주 전 확인 사항

  1. Gb/s와 GB/s 불일치: Components에 200 GB/s (4x 200 Gb/s or 2x 400 Gb/s NICs)와 400 GB/s (4x 400 Gb/s NICs)가 적혀 있다. 괄호 안 링크 수를 단방향 선속도로 합산하면 각각 100GB/s, 200GB/s다. 양방향 aggregate를 의도한 것인지 단위/산식 오류인지 명시되지 않아 제조사 확인이 필요하다. 본 문서는 §3의 구체적 포트 BOM 기준 계산만 사용한다.[1]
  2. NIC 수 불일치: 부록 Table 9/10의 라벨은 Compute fabric (8/node)지만 16/32노드 열의 수량은 64/128개, 같은 부록의 node BOM은 4개/node다. 라벨을 근거로 NIC 8개를 발주하지 않는다.[7]
  3. 70B 단일 GPU 추론의 조건 누락: Physical Topologies는 약 40B FP16 이후 모델 병렬 가능성을 설명하면서, pure inference 단락에서는 정밀도 없이 GPU당 약 70B를 언급한다. 계산상 70B FP16 가중치만 140GB이므로 96GB 한 장에 그대로 맞지 않는다. 4bit 단순 가중치는 35GB지만 quantization metadata·KV cache·workspace가 추가된다. 양자화와 context 조건을 확정하기 전 용량 보장으로 쓰지 않는다.[3][9]
  4. “multi-GPU inference에 성능 이득이 없다”는 일반화 금지: RA의 pure-inference 단락은 replica 처리량 관점의 설계 지침으로 제한해서 읽는다. 모델 적재 가능성, per-request latency, batch, context, parallelism에 따른 실제 결과를 대체하지 못한다.[3]
  5. Switch·광모듈 수량: 물리 800G 포트, breakout 400G endpoint, node-side와 switch-side transceiver의 수를 구분한다. 부록 자체도 정확한 BOM/part number를 OEM/ODM 및 NVIDIA support와 확정하라고 명시한다.[2][4][7]

원문

7. 도입 전 측정·인수 검증 — 실행 결과가 아닌 권고 체크리스트

  1. 지원 조합 고정: GPU edition/part number, OEM server, BIOS/BMC, PCIe switch firmware, NIC/DPU firmware, driver/CUDA/NCCL, container image digest, switch NOS, 광모듈을 BOM과 함께 기록한다.
  2. 노드 topology 검증: nvidia-smi -L, nvidia-smi topo -m, lspci -tv로 장치·NUMA·연결을 기록하고, GPU pair별 P2P bandwidth/latency를 측정한다. 링크 폭·속도와 CPU 우회 여부를 확인한다.
  3. E/W 검증: host-to-host RDMA와 GPU-to-GPU RDMA를 구분한 뒤, 동일/다른 rail의 NCCL AllReduce·AllGather·ReduceScatter·AlltoAll을 측정한다. NIC/PCIe/CPU 사용량으로 staging 또는 TCP fallback 여부를 확인한다.
  4. 실제 workload 검증: 동일 모델·정밀도·context·batch에서 단일 GPU replica와 TP를 비교한다. 추론은 TTFT·TPOT·p95/p99·SLO 내 처리량, 학습은 step time·통신 비중·확장 효율을 사용한다.
  5. 동시 부하·장애 검증: model load/checkpoint와 추론 동시 실행, NIC/link/switch/전원 feed 장애, 재스케줄·checkpoint 복구를 시험한다. E/W·N/S 통합형은 queue 경합과 tenant 간 간섭도 확인한다.
  6. 열·운영 검증: 장시간 부하의 throttling, ECC/Xid, fan/전력, MIG 변경과 drain, DPU/OOB 복구를 확인한다. 합격 기준은 내부 SLO와 OEM 보증 조건으로 발주 전에 합의한다.

구체적인 RoCE QoS·GPU–NIC 매핑·단계별 통신 검증은 roce-fabric-configuration-validation을 따른다. 문서와 산술 검증은 완료했지만 이 체크리스트의 하드웨어 시험은 수행하지 않았다.
