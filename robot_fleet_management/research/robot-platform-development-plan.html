로봇 관제 플랫폼 개발 목록과 EPIC 분류

개발 전략과 산출물

이 문서는 제안 백로그다. 실제 현대자동차 요구사항이나 견적 확정본이 아니다. EPIC은 하나의 제품 성과를 묶은 큰 개발 단위이고, 스토리는 사용자가 얻을 가치와 검증 가능한 수용 조건을 가진 항목이다.

기술 근거는 Open-RMF의 multi-fleet 범위, VDA 5050의 통신 경계와 범위 제외, OT의 신뢰성·안전을 함께 다루는 NIST 소개다.[10][11][9] 개발 패키지의 세부 분해·일정·담당은 이 위키의 설계 제안이다.

12개 EPIC → 48개 개발 패키지 → 120개 핵심 스토리로 추적한다. 각 EPIC의 패키지 4개는 스토리 01–03 / 04–06 / 07–08 / 09–10을 순서대로 묶는다. 패키지는 별도의 추가 스토리 개수를 뜻하지 않는다.

EPIC 분류와 책임

아래 “의존”은 먼저 필요한 최소 계약·인터페이스다. 해당 EPIC 전체 완료를 기다리라는 뜻이 아니다. E09·E10·E11의 기본 통제는 착수부터 병행하고 모든 출시의 공통 게이트로 적용한다.

  • E01 자산·현장 모델 — 목표: 동일한 로봇·지도·설비를 모든 모듈이 같은 뜻으로 해석. 책임: 플랫폼 도메인 팀. 의존: 현장 자산 조사.
  • E02 이기종 연동 — 목표: 지원 계약에 맞는 명령·상태 변환. 책임: 로봇 연동 팀. 의존: E01 ID/능력 모델.
  • E03 임무·명령 생명주기 — 목표: 요청부터 물리 인계까지 추적·대조. 책임: 코어 백엔드 팀. 의존: E01/E02 계약.
  • E04 배차·생산 우선순위 — 목표: 납기와 능력 제약을 충족하는 배차. 책임: 스케줄링 팀+생산기술. 의존: E03 상태/E06 업무 의미.
  • E05 교통·공유 자원 — 목표: 예약·점유·인계를 일관되게 조정. 책임: 로봇 제어 연동 팀. 의존: E01 지도/E02 제어 범위.
  • E06 제조업무 통합 — 목표: 생산·재고·품질과 인계 실적의 정합성. 책임: 제조 IT 팀. 의존: E01/E03 계약.
  • E07 운영 UX·예외 대응 — 목표: 교대 운영자가 상태를 판단하고 승인된 복구를 수행. 책임: 제품/프런트엔드+현장 운영. 의존: E03/E05/E06 사건 모델.
  • E08 엣지·신뢰성·망 — 목표: 단절·재시작에서도 명령 권한과 상태를 복구. 책임: 플랫폼/SRE+OT 네트워크. 의존: E02/E03 영속성 계약.
  • E09 보안·거버넌스 — 목표: 허용된 주체만 승인된 명령을 실행. 책임: 보안+플랫폼. 의존: 공장 IAM/접속 정책.
  • E10 안전 검증·운영 통제 — 목표: 위험 분석·책임·시험 증거와 재개 절차를 관리. 책임: 안전 책임자+자동화/운영. 의존: 현장 위험 조사; 기능 개발 전 시작.
  • E11 시험·시뮬레이션·출시 — 목표: 정상·장애 조건을 반복 검증하여 출시 승인. 책임: QA/플랫폼+공급사. 의존: 최소 계약부터 시험 병행.
  • E12 분석·멀티공장·지능화 — 목표: 지표와 비용의 근거를 남기고 검증된 구성을 재사용. 책임: 데이터/제품+공장 운영. 의존: E01/E03/E07 사건 품질.

우선순위와 완료의 의미

  • P0: 첫 생산 파일럿을 열기 전에 필요한 기능·통제. 계획상 M1~M12 구간에서 완료한다.
  • P1: 2년 목표의 운영 안정화·확장에 필요. 계획상 M13~M24에 완료한다.
  • P2: 3~5년 옵션. 선행 조건과 가치가 검증되지 않으면 착수하지 않는다.

현재 제안은 P0 70개, P1 38개, P2 12개다. 첫 2년 범위는 P0+P1의 108개이며 스토리 개수는 작업량·인월이 아니다. 현장 접근권과 팀 역량을 확인한 뒤 크기·의존성을 재산정하고, 필요한 경우 범위 또는 일정을 조정한다.

스토리의 일정은 검증을 마칠 목표 구간이지 개발 시작일이 아니다. E09/E10의 기본 권한·안전 검토는 P0 통제로 먼저 들어가고 나중 스토리는 고도화다. 파일럿에 필요 없다고 입증된 항목을 제외하려면 현장·안전·제품 책임자의 근거 있는 변경 승인이 필요하다.

공통 DoD(완료 기준): 코드/설정 검토, 계약·회귀 시험, 권한 부정 시험, 장애·복구 영향 검토, 지표·로그, 운영 안내, 되돌리기 방법, 지정 책임자 승인. 안전 관련 항목은 적격 안전 담당자의 현장 평가를 추가한다. 단위시험 통과를 현장 안전 적합성으로 대신하지 않는다.

자체 개발·재사용·구매 경계

  • 직접 소유할 것: 업무 임무 모델·생산 인계 의미·복구 워크플로·운영 경험·공장별 구성 계약.
  • 검증 후 재사용할 것: Open-RMF 등 조정 기반, DB·브로커·관측 도구·신원 제공자. 라이선스, 보안 지원 기간, 업그레이드와 현장 유지보수 능력으로 비교한다.[10]
  • 공급사에 남길 것: 로봇 내부 주행·기구 제어, 인증된 안전 기능, 제조사 고유 진단. 인터페이스와 지원 SLA는 계약으로 확보한다.

VDA 3.0.0 릴리스는 자유주행 지원과 파라미터의 breaking 변경 등을 명시한다.[8] “가장 높은 버전”을 강제하기보다 대상 장비의 2.x/3.x 프로파일을 분리하고 상호운용 시험 결과로 지원표를 발행한다. 규범 PDF와 schema 대조는 구현 착수의 선행 산출물이다.

조직·비용·일정 산정

제품/현장 분석, 코어·연동, 제조 IT, UX, 플랫폼/SRE, QA, 보안, 안전·OT 전문가 역할이 필요하다. 역할과 전담 인원수는 다르므로 아직 인원이나 총액을 확정하지 않는다. 공급사·현장 접근권이 없으면 개발 인력을 늘려도 통합 검증을 앞당기기 어렵다.

패키지별 낙관/기준/비관 인월을 M3까지 추정한다. 비용 모델은 개발 인월×단가 + 장비/시험장 + 공급사 라이선스·지원 + 현장 통합/안전 검증 + 운영 인프라·지원 + 재검증 예비비다. 절감 효과는 물류 인력의 실제 재배치·관제 기인 대기·유지보수 비용으로 분리하고 생산량 증가와 인건비 절감을 중복 계상하지 않는다.

위험과 미해결 항목

가장 큰 일정 위험은 API 접근 제한, 공급사별 예외 의미, 지도·현장 불일치, 실제 안전 검증 지연이다. 설계 변경 기록(ADR)에 통제 방식, 데이터 원장, 지도·시간 계약, 명령 단일성, 복구, 프로토콜 버전, 배포 방식과 build/buy 결정을 남긴다.
