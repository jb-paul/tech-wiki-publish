기반 기능 EPIC E01–E04 핵심 스토리

범위와 표기

VDA 5050 3.0.0은 로봇·관제 통신을 정의하지만 교통 알고리즘·업무 연동·안전·보안을 해결하는 완제품은 아니다.[11] 아래는 이 경계에서 도출한 플랫폼 개발 제안이며 규격의 필수 요구 목록이 아니다.

각 EPIC의 10개 스토리는 모두 제안 상태다. 제목 다음에 사용자 가치, 다음 줄에 합격을 판단할 관찰 가능한 조건을 쓴다. 단계는 완료 목표이며 시작일이 아니다. P0=M12 이내 첫 파일럿 필수, P1=M24 이내 제품화, P2=Y3~Y5 옵션이다. 실제 착수월과 용량·허용 오차는 현장 합의 후 확정한다. 수용 조건의 시험 통과는 현장 전체의 무사고·무결함 보장이 아니다.

공통 DoD·패키지 매핑은 robot-platform-development-plan, 지표·게이트는 robot-platform-five-year-roadmap을 따른다.

E01 — 자산·현장 모델

  • E01-01 · 공장·구역 ID (P0, M6) — 현장 관리자로서 자산의 소속을 식별해 다른 공장에 명령하지 않으려 한다.

    • 수용 기준: 다른 공장의 동일 자산명이 있을 때 ID로 구분되고 타 공장 명령은 거부·기록된다.

  • E01-02 · 로봇 능력 등록 (P0, M6) — 연동 담당자로서 적재·치수·도구 조건을 등록해 수행 불가능한 배차를 막으려 한다.

    • 수용 기준: 능력이 없거나 검증되지 않은 로봇에 조건부 작업을 요청하면 배차 후보에서 제외되고 이유가 남는다.

  • E01-03 · 설비·공유 자원 등록 (P0, M6) — 자동화 담당자로서 도킹·충전·통로 자원을 식별해 실제 설비와 예약을 연결하려 한다.

    • 수용 기준: 존재하지 않거나 사용 중지된 자원을 참조한 임무가 실행 전에 거부된다.

  • E01-04 · 지도 버전 지정 (P0, M9) — 현장 엔지니어로서 승인된 지도만 사용해 장소 불일치를 막으려 한다.

    • 수용 기준: 관제와 로봇의 지도 버전이 맞지 않으면 해당 구역 신규 지시를 보류하고 차이를 표시한다.

  • E01-05 · 좌표계 검증 (P0, M9) — 연동 담당자로서 좌표 변환을 검증해 목적지가 바뀌는 오류를 찾으려 한다.

    • 수용 기준: 합의한 기준점과 방향 시험에서 허용 오차를 벗어나면 지도 활성화를 거부한다.

  • E01-06 · 작업 지점 유효성 (P0, M9) — 물류 담당자로서 출발·인계·대기 지점을 구분해 잘못된 도킹을 방지하려 한다.

    • 수용 기준: 용기/로봇과 호환되지 않는 인계점을 지정하면 임무 검증이 실패하고 대안을 안내한다.

  • E01-07 · 정비 상태 관리 (P0, M12) — 정비 담당자로서 정비 중 로봇을 제외해 작업 중단을 예방하려 한다.

    • 수용 기준: 정비 전환 시 신규 배차가 차단되고 진행 임무는 합의된 인계 절차로만 처리된다.

  • E01-08 · 부착물 구성 (P1, M18) — 정비 담당자로서 도구 교체 이력을 남겨 변경된 능력을 배차에 반영하려 한다.

    • 수용 기준: 부착물 변경 뒤 검증 승인이 없으면 관련 작업 능력이 활성화되지 않는다.

  • E01-09 · 구성 승인·되돌리기 (P1, M21) — 공장 관리자로서 변경을 검토하고 이전 구성으로 돌아가고자 한다.

    • 수용 기준: 새 구성 승인자·영향 임무·버전이 기록되고 되돌리기 후 진행 임무와 충돌 여부를 대조한다.

  • E01-10 · 자산 이력 내보내기 (P1, M24) — 감사 담당자로서 자산 변경 이력을 확인해 장애 당시 구성을 재현하려 한다.

    • 수용 기준: 자산·시간을 지정하면 당시 지도·능력·설비 구성과 승인 근거를 권한 범위 내에서 내보낸다.

E02 — 이기종 연동

  • E02-01 · 어댑터 개발 계약 (P0, M6) — 연동 개발자로서 공통 SDK 계약을 사용해 공급사 차이를 격리하려 한다.

    • 수용 기준: 가짜 장비와 실제 지원 장비를 같은 계약 시험에 넣어 상태·명령·오류 필수 항목을 검사한다.

  • E02-02 · VDA 버전 프로파일 (P0, M9) — 연동 담당자로서 장비별 적용 버전을 고정해 묵시적 변환 오류를 막으려 한다.

    • 수용 기준: 2.x/3.x 대상의 지원 필드·동작·규범 PDF/schema 목록이 고정되고 미지원 버전은 실행 전 거부한다.

  • E02-03 · 공급사 API 연결 (P0, M9) — 통합 담당자로서 비표준 장비도 연결해 기존 자산을 활용하려 한다.

    • 수용 기준: 승인된 공급사 API의 명령·상태·권한 시험과 단절 시험이 실제 대상 장비에서 통과한다.

  • E02-04 · 지원 능력 계약 (P0, M9) — 운영자로서 지원되는 취소·일시정지 범위를 알아 잘못된 조작을 피하려 한다.

    • 수용 기준: 미지원 동작은 UI/API 양쪽에서 차단되고 버전별 지원표와 오류 사유가 일치한다.

  • E02-05 · 상태 정규화 (P0, M6) — 관제 운영자로서 원본 상태와 해석을 함께 보아 오판을 줄이려 한다.

    • 수용 기준: 관측/수신 시각·순서·원본 오류를 보존하고 오래되거나 미지의 상태를 정상으로 매핑하지 않는다.

  • E02-06 · 응답 단계 구분 (P0, M6) — 백엔드 개발자로서 명령 수신과 물리 완료를 분리하려 한다.

    • 수용 기준: 수신 ACK만 도착한 시험에서 임무는 완료되지 않고 별도 완료 증빙을 기다린다.

  • E02-07 · 재접속 상태 대조 (P0, M12) — 운영자로서 재접속 후 실제 작업을 확인해 중복 운반을 막으려 한다.

    • 수용 기준: 완료 직전 단절 후 연결해도 진행/완료 상태를 조회·대조하기 전 같은 물리 작업을 재지시하지 않는다.

  • E02-08 · 불량 메시지 격리 (P0, M12) — 연동 개발자로서 비정상 메시지가 전체 관제를 멈추지 않게 하려 한다.

    • 수용 기준: 잘못된 schema·과대 payload·역순 상태를 주입해 격리·진단하고 정상 장비 처리가 지속됨을 확인한다.

  • E02-09 · 공급사 적합성 묶음 (P1, M24) — 구매·QA 담당자로서 재현 가능한 시험으로 지원 주장을 검토하려 한다.

    • 수용 기준: 공급사·모델·펌웨어·프로파일별 정상/오류/재접속 결과와 미지원 항목을 보고서로 발행한다.

  • E02-10 · 어댑터 호환 업그레이드 (P2, Y3) — 플랫폼 운영자로서 어댑터를 바꿔도 기존 임무를 보존하려 한다.

    • 수용 기준: 이전/후속 버전 계약 회귀와 실패 시 되돌리기를 시험하고 진행 임무의 해석이 달라지면 배포를 차단한다.

E03 — 임무·명령 생명주기

  • E03-01 · 중복 안전 접수 (P0, M6) — 업무 연동자로서 같은 요청을 재전송해도 한 임무로 추적하려 한다.

    • 수용 기준: 같은 요청 ID·내용을 반복하면 같은 임무를 반환하고, 같은 ID에 다른 내용이면 충돌을 기록한다.

  • E03-02 · 명시적 상태기계 (P0, M6) — 운영자로서 임무가 멈춘 단계를 알아 정확히 조치하려 한다.

    • 수용 기준: 허용되지 않은 상태 전이를 거부하고 상태불명·보류·취소요청을 완료와 구분한다.

  • E03-03 · 명령 저널·outbox (P0, M6) — 백엔드 담당자로서 응답 전후 장애를 추적해 명령 유실을 대조하려 한다.

    • 수용 기준: 기록/전송 경계에서 프로세스를 종료해도 승인된 요청의 기록과 재전송 대상이 식별된다.

  • E03-04 · 물리 인계 완료 (P0, M9) — 물류 담당자로서 올바른 인계 증빙으로만 업무를 종료하려 한다.

    • 수용 기준: 로봇 도착만 있고 스캔/설비 수락이 없으면 임무는 완료되지 않고 인계 확인 대기로 남는다.

  • E03-05 · 취소 수명주기 (P0, M9) — 운영자로서 취소 진행과 결과를 알아 적재물을 방치하지 않으려 한다.

    • 수용 기준: 취소 응답 유실·거부·적재 중 상황을 각각 시험하고 현장 대조 없이 취소완료로 바뀌지 않는다.

  • E03-06 · 보류·재개 계약 (P1, M15) — 운영자로서 중단된 작업을 승인 절차로만 재개하려 한다.

    • 수용 기준: 보류 원인이 해소돼도 권한·점유·장비 상태 검증과 필요한 승인 전에는 신규 실행 명령이 나가지 않는다.

  • E03-07 · 적재 작업 재할당 (P1, M18) — 물류 운영자로서 고장 난 로봇의 물품을 확인한 뒤 대체 운반하려 한다.

    • 수용 기준: 회수/인계 증빙 없는 적재 임무의 자동 재할당을 거부하고 새 임무와 원 임무 연결을 남긴다.

  • E03-08 · 다단계 임무 보상 (P1, M18) — 업무 설계자로서 일부 단계 실패를 추적해 실제 인계를 되돌렸다고 오인하지 않으려 한다.

    • 수용 기준: 하역 완료 후 후속 단계 실패 시 물리 완료 이력을 유지하고 승인된 회수·대체 단계만 생성한다.

  • E03-09 · 재시작 대조 큐 (P0, M12) — 운영자로서 상태가 불명인 작업을 찾아 안전하게 복구하려 한다.

    • 수용 기준: 재시작 시 원장·장비·설비가 불일치한 작업을 대조 큐에 넣고 자동 완료/공간 해제를 하지 않는다.

  • E03-10 · 업무 통지 재전송 (P0, M12) — MES/WMS 담당자로서 결과 응답 유실을 복구해 원장을 맞추려 한다.

    • 수용 기준: 완료 통지를 반복해도 업무 실적은 중복 반영되지 않으며 미수락 통지가 목록과 알람에 남는다.

E04 — 배차·생산 우선순위

  • E04-01 · 능력·상태 필터 (P0, M9) — 생산기술 담당자로서 할 수 있는 장비만 선택해 현장 실패를 줄이려 한다.

    • 수용 기준: 중량·도구·지도·정비·통신 조건이 부적합한 후보가 제거되고 제거 근거가 저장된다.

  • E04-02 · 마감 기반 우선순위 (P0, M9) — 물류 담당자로서 납기와 대기 노화를 반영해 결품·장기 대기를 줄이려 한다.

    • 수용 기준: 마감·긴급도·노화가 다른 고정 trace에서 승인된 규칙대로 선택되고 선택 사유가 재현된다.

  • E04-03 · 단순 배차 기준선 (P0, M9) — QA 담당자로서 재현 가능한 기준 정책으로 개선을 비교하려 한다.

    • 수용 기준: 동일 입력/버전/조건에서 기준 정책의 배차 기록이 재현되고 정책 설정이 보고서에 포함된다.

  • E04-04 · 생산 순서 변경 (P1, M18) — 라인 담당자로서 순서가 바뀐 작업을 승인 정책에 맞게 재조정하려 한다.

    • 수용 기준: 적재 전/후 순서 변경을 구분해 보류·우회·재할당 여부를 결정하고 기존 물품 추적을 잃지 않는다.

  • E04-05 · 충전 계획 (P1, M18) — 운영자로서 충전 대기를 반영해 운행 중 전력 부족을 예방하려 한다.

    • 수용 기준: 공급사가 승인한 배터리 조건과 예약 충전기를 만족하지 못하면 새 임무를 배정하지 않고 이유를 표시한다.

  • E04-06 · 대체 목적지 선택 (P1, M18) — 물류 담당자로서 인계점 불능 때 승인된 대기 지점을 활용하려 한다.

    • 수용 기준: 불능 목적지 임무는 호환 능력·용량·승인을 확인한 대안만 선택하고 원래 업무 요청과 연결된다.

  • E04-07 · 기아 탐지 (P1, M18) — 운영자로서 계속 밀리는 작업을 찾아 방치된 주문을 줄이려 한다.

    • 수용 기준: 우선순위 높은 작업을 반복 주입하면 합의된 대기 기준 초과 임무가 탐지되고 조치 이력이 남는다.

  • E04-08 · 수동 우선순위 조정 (P1, M18) — 생산 책임자로서 긴급 요청을 반영하되 영향을 확인하려 한다.

    • 수용 기준: 변경 사유·권한·영향받는 임무·승인이 기록되고 안전/능력 제약은 우선순위로 우회되지 않는다.

  • E04-09 · Shadow 정책 비교 (P2, Y4) — 제품 책임자로서 신규 정책을 제어권 없이 비교하려 한다.

    • 수용 기준: 동일 trace에서 기준/후보의 납기·최장대기·개입 지표를 비교하고 후보가 실제 명령을 보내지 않음을 검증한다.

  • E04-10 · 제한적 최적화 배포 (P2, Y4) — 운영 책임자로서 효과가 증명된 정책만 제한적으로 적용하려 한다.

    • 수용 기준: 허용 구역·평가기간·악화 기준을 사전 승인하고 기준 초과 시 기존 정책으로 복귀·임무 대조한다.

의존성·한계와 연결

각 항목은 명세 초안이다. 공급사 기능·명령 권한·현장 위험 평가 결과에 따라 구현을 분리하거나 범위를 조정한다. P0 기능을 미구현 상태로 생산 확대하려면 된다고 가정하지 말고 파일럿 범위를 재승인한다. 상세 의존성은 개발계획의 EPIC 계약을 따른다.
