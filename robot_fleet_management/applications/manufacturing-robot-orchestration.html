제조환경의 로봇 관제와 생산 연계 설계

제조 관제는 무엇이 다른가

공장에서는 “빨리 옮겼다”만으로 충분하지 않아요. 맞는 부품을, 필요한 순서대로, 제시간에 건네야 해요. 다음 차에는 다른 사양의 부품이 필요한데 앞 차의 부품을 가져오면 이동시간이 아무리 짧아도 도움이 되지 않죠. 여기서 다루는 상황은 요구사항을 설명하기 위한 가상 사례이며 특정 공장의 실제 공정이나 성과는 아니에요.

공개 자료에서 HMGICS는 셀 기반 생산과 디지털 트윈을, HMGMA는 AGV 물류·용접공장 검사·조립공장 주차 로봇 활용을 설명해요.[5][6] 셀은 작업을 수행하는 생산 단위이고, 디지털 트윈은 실제 현장을 디지털 공간에 연결해 표현하는 개념이에요. 이 사례는 생산·검사·설비를 함께 고려할 이유를 보여 주지만, 내부 관제 설계까지 알려 주는 것은 아니에요. 원문 원문

제조 요구를 시스템 요구로 바꾸기

현장 용어를 바로 개발 항목으로 옮기기보다, 각각 어떤 상황을 뜻하는지 먼저 볼게요.

  • Takt와 납기: takt는 고객 수요에 맞춰 제품을 생산해야 하는 간격이에요. 로봇을 배차하는 주기와 같은 값은 아니에요. 관제에는 부품 투입 예정 시각, 라인 옆 재고가 떨어질 예상 시각, 인계 마감을 전달하도록 해요.
  • JIT와 JIS: JIT는 필요한 때 공급하는 것, JIS는 생산 순서까지 맞춰 공급하는 데 초점을 둬요. “제시간에 왔지만 다음 차의 부품이 아니에요”라는 문제도 막아야 하죠. 차체가 보류되거나 재작업 순서가 바뀌면 배차·인계를 어떻게 멈추거나 바꿀지도 정해야 해요.
  • 혼류생산: 한 라인에서 서로 다른 사양의 제품을 만드는 상황이에요. 어떤 제품에 어떤 용기와 부품이 연결되는지 확인하고, 필요한 작업을 할 수 없는 로봇은 배차 대상에서 빼야 해요.
  • 설비 연결: 로봇이 도착했다고 설비가 받을 준비를 마친 것은 아니에요. 설비에 맞춰 붙는 도킹, 물품 전달, 설비의 수락을 각각 확인하고, 단계별로 누가 지시하며 무엇을 증거로 볼지 정해요.
  • 사람과 동선 공유: 작업자·지게차·정비 구역을 지도에 표시해요. 다만 화면에 금지 구역을 그렸다는 이유만으로 실제 위험을 막는 보호 기능이 갖춰졌다고 볼 수는 없어요.
  • 교대와 현장 변경: 다음 교대가 모르는 장애를 남기면 안 되겠죠. 미해결 문제를 인수인계하고 휴식, 생산 전환, 금형 교환, 공사 일정도 반영해요.
  • 브라운필드: 이미 가동 중인 기존 공장을 말해요. 좁은 통로, 무선 통신이 잘 안 되는 곳, 오래된 PLC와 제조사 관제가 있을 수 있어요. 이런 조건을 유지하며 조금씩 연결해야지 새 공장처럼 한 번에 바꿀 수 있다고 가정하면 곤란해요.

공정별 연결 범위 — 후보

공정마다 연결할 대상도 달라요. 다음은 검토할 범위이지, 모든 공정에 같은 장비를 넣겠다는 뜻은 아니에요.

  • 입고·창고: 창고 관리 시스템인 WMS의 출고지시를 받고, 어떤 용기를 옮기는지 스캔으로 확인해요. 평소와 다른 곳에 내려놓는 예외 적치와 빈 용기 회수도 포함해요.
  • 차체·용접: 고정형 로봇 셀이 준비됐는지, 작업 중인지, 고장인지와 자재 전달을 연결해요. 용접 로봇의 세부 움직임과 안전 PLC 제어는 별도로 남겨 둡니다. PLC는 산업 설비용 제어기예요.
  • 도장: 오염이나 폭발 위험을 막는 방폭 등 별도 환경 요구가 있을 수 있어요. 전문가 검토 전에 일반 물류 로봇을 그대로 적용하지 않아요.
  • 조립: 라인 옆으로 부품을 보내고 순서를 맞춰요. 부품 부족, 재작업으로 빠지는 물품, 작업자가 받는 절차도 다룹니다.
  • 배터리·중량물: 물품의 무게와 무게중심, 고전압, 화재 대응을 먼저 검토해요. 운반 장비가 실제 물품과 위험 조건에 맞는지도 확인해야 해요.
  • 검사·완성차: 검사를 시키고 결과를 모으는 일, 합격 여부를 정하는 일, 차량을 옮기는 일을 구분해요. 관제가 검사 요청을 관리한다고 품질 승인까지 맡는 것은 아니에요.

시스템 원장과 인계 계약

기록이 서로 다르면 무엇을 기준으로 판단할지 정해 둬야 해요. 여기서 원장은 ‘최종 기준으로 삼는 기록’이라고 생각하시면 됩니다. 같은 재고를 두 시스템이 각자 확정하면 값이 어긋나기 쉽죠. 다음 역할 분담을 제안하되, 실제 공장 담당자와 확정해야 해요.

  • MES(생산 실행 관리): 생산지시, 차체·제품 번호, 공정 순서와 생산 보류를 책임져요.
  • WMS(창고 관리): 자재·용기·재고와 출고 예약·실적을 책임져요.
  • QMS(품질 관리): 검사 기준, 결과 승인, 부적합과 품질 보류 해제를 책임져요.
  • 관제: 작업 배정, 명령 이력, 통로·설비의 예약과 실제 사용 상태, 복구 진행을 책임져요.
  • 로봇·PLC: 실제 동작과 현장 상태를 알려 줘요. 공급사 오류 코드와 센서가 무엇을 뜻하는지도 연결 약속에 적어야 해요.

VDA 5050은 외부 IT나 주변 설비의 연결 방식까지 규정하지 않아요.[11] 그래서 MES/WMS API, 산업용 정보 교환 방식인 OPC UA, 기존 PLC의 신호 접점을 어떻게 쓸지는 따로 정해야 해요. 연결 방식이 같아도 “인계 완료”의 의미가 저절로 맞춰지지는 않거든요. 원문

한 건의 자재 공급을 따라가기 — 가상 시나리오

부품 상자를 라인에 가져다주는 일을 처음부터 따라가 볼게요. 아래는 설명을 위한 흐름이지 실제 시험 결과는 아니에요.

  1. 생산계획이 바뀌면 MES가 새 투입 정보를 보내고, WMS가 맞는 부품 상자를 예약해요.
  2. 관제는 원래 요청 ID, 용기, 출발·목적지, 마감과 완료 확인 방법을 묶어 작업을 만들어요.
  3. 짐을 실을 능력이 있고 같은 지도를 사용하는 로봇을 골라 배차해요.
  4. 출발지에서 상자를 스캔하고 인수 사실을 남겨요. 요청과 다른 상자라면 출발을 보류합니다.
  5. 이동 중 생산 순서가 바뀌면 승인된 규칙에 따라 기다리거나 다른 곳에 내려놓게 해요. 이미 짐을 실은 작업을 아무 확인 없이 취소하거나 다른 로봇에 넘기면 안 돼요.
  6. 목적지 설비가 물품을 받았고 하역이 끝났다는 증거를 확인한 뒤 업무 완료를 보고해요.
  7. 완료 응답이 사라지면 같은 요청 ID로 다시 알리되, 새 운반은 만들지 않아요. 실제 상태를 모르는 작업은 운영자가 확인할 목록에 남깁니다.

고장과 운영 부담을 먼저 설계한다

정상 흐름만큼 중요한 것이 “중간에 멈추면 누가 무엇을 확인하나?”예요.

  • 짐을 실은 채 고장 났다면: 다른 로봇부터 보내지 말고 물품이 어디 있는지, 누가 맡고 있는지, 어떻게 회수할지 확인해요.
  • 무선 통신이 끊겼다면: 마지막으로 받은 정보가 언제 것인지 보여 줘요. 응답 제한시간인 timeout이 지났다고 통로가 비었다고 처리하면 안 돼요. 로봇이 그대로 있을 수도 있어요.
  • 설비가 받을 수 없다면: 설비가 받을 수 없는 상태임을 기록하고 인계를 보류해요. 다른 곳에 놓거나 사람이 처리할 때의 승인 기록을 남겨요.
  • 중앙 시스템과 연결이 끊겼다면: 공장 안에서 이미 승인된 작업만 계속해요. 새로운 생산계획이나 승인이 필요한 일은 보류하고, 연결이 돌아오면 기록을 맞춰 봐요.
  • 화재나 비상상황이라면: 현장 안전 절차를 따라야 해요. 관제는 이를 돕지만 일반 네트워크 명령이 비상정지 회로를 대신하지는 않습니다.

안전·보안의 적용 경계

로봇 팔을 작업 셀에 설치할 때의 위험과, 그 로봇이 바퀴 달린 장비 위에서 이동할 때의 위험은 같지 않아요. ISO 10218-2:2025의 공개 미리보기는 산업용 로봇 응용·셀 통합을 다루지만, 이동 플랫폼이나 무인 산업차량에 통합된 로봇의 이동성 관련 위험은 제외한다고 밝혀요.[12] 로봇 팔과 이동 기능을 함께 가진 이동 매니퓰레이터를 셀 규격 하나로 전부 검증했다고 보면 안 되는 이유예요. 원문

무인 산업차량 관련 ISO 3691-4:2023도 검토 후보지만, 이번 조사에서는 공식 본문을 확보하지 못했어요. 상세 조항이나 적용 여부를 판정하지 않았고, 국가별 법규와 공장 안전 기준도 따로 검토해야 합니다.

NIST SP 800-82 Rev.3 소개는 OT의 물리적 영향, 성능, 신뢰성, 안전을 함께 고려해요.[9] OT는 현장 설비의 동작을 제어·관찰하는 영역이에요. 이 문서에서는 생산망을 구분하고, 승인된 공급사만 접속하게 하며, 필요한 권한만 주고, 장애 뒤 현장에서 복구할 수 있게 설계하자고 제안해요. NIST 준수를 확인했다는 뜻은 아니에요. 원문

현장 검증과 남은 질문

개선 효과를 비교하려면 같은 작업이 들어오도록 해야 해요. 작업 종류와 도착 순서를 기록한 trace를 재생하고, 교대·제품 구성을 맞춘 상태에서 정시 인계, 잘못된 인계, 사람의 개입, 관제 때문에 생긴 대기를 비교해요. 로봇을 더 넣었더니 교차로나 충전기가 더 막히는지도 봐야 합니다.

어느 공정인지, 물류량과 작업자 통행이 어느 정도인지, 장비가 무엇을 지원하는지, 생산 중 얼마나 멈춰도 되는지는 아직 몰라요. 안전 책임자와 요구사항도 확정해야 하고요. 이 상태에서 절감률이나 전 공장 구축비를 확정하기보다는 현장 자료를 먼저 받는 것이 순서예요.
